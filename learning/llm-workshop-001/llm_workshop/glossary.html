LLM terms, in plain language

A companion to Open the model. Each term has an explanation and an example. Examples labeled “invented” illustrate the idea; they are not measurements from our model.

Choose the character workshop (32 vocabulary entries, 64 positions) or the whole-word companion (52 vocabulary entries, 16 positions). Both use 64 features, two transformer blocks and two heads per block. Their browser predictions are calculated live from separate checkpoints. Before/after training results were recorded in Python; the word model was trained on the local RTX 2080 SUPER. Word-route examples and Python commands.

Use your browser's Find command to locate a term, or choose a section below. This page works offline, requires no JavaScript and can be printed.

Learn these first

Follow this short route before the more detailed terms:

  1. Language model: a system that predicts text pieces.
  2. Token and tokenizer: what counts as a piece, and how it gets an ID.
  3. Weights: stored numbers used in the calculation.
  4. Embedding: the vector looked up using a token ID.
  5. Attention: how a position combines information from allowed positions.
  6. Generation: predict, choose, append, repeat.
  7. Training and loss: how examples lead to weight updates.
  8. Retrieval versus fine-tuning: changing evidence in the input versus learned parameters.
The question to keep asking: what changed?

Typing changes the input and computed values. Sampling selects an output. Loading a checkpoint replaces stored weights. Training updates weights using examples.

1. The system we are opening

NLPLanguage model / LLMTransformer / GPTArchitectureParameters / weights / biasActivationsBase and instruction modelsAssistant / agent

NLP — natural language processing

The field of computing concerned with human language. Its tasks include classification, search, translation and text generation. Language models are one approach within this broader field.

Example: labeling a financial sentence “positive” is an NLP task, even if the system never writes a paragraph.

Language model and LLM

A language model assigns probabilities to text sequences. The kind used here does this by predicting the next token from the preceding context. LLM means large language model; there is no single parameter count at which every model becomes “large”. Our tiny models demonstrate the mechanism at a small scale.

In the word companion: after “the small cat”, inspect the measured probabilities for “sleeps”, “rests” and other vocabulary entries. In the character route, the same process predicts individual characters.

A likely continuation is not automatically a true statement.

Transformer and GPT

A transformer is a neural-network architecture built around attention and other transformations of token representations. GPT stands for Generative Pretrained Transformer. “GPT-style” describes the causal architecture used here; it does not mean our freshly initialized model has already been pretrained.

In this workshop: TinyGPT passes representations through two transformer blocks before scoring possible next characters.

Architecture

The arrangement of calculations: which layers exist, their dimensions and how their outputs connect. It is the model's structure. Parameters are the particular numbers placed inside that structure.

Example: the untrained and 200-update browser checkpoints have the same two-block architecture but different parameter values.

Parameters, weights and bias

Parameters are stored numbers that learning can adjust. “Weights” is often used broadly for all parameters; more specifically, weights multiply inputs, while a bias adds an offset. Embedding tables and normalization parameters are also learned parameters.

Invented example: in output = 2 × input + 0.5, 2 is a weight and 0.5 is a bias. Training could change both.

Editing a prompt does not itself update these numbers. The character browser model has 108,320 parameters; the word companion has 107,828.

Activation

A value computed while processing a particular input, such as an embedding-plus-position vector or a block output. Activations can change immediately when the input changes even though parameters stay fixed.

Example: changing “cat” to “dog” changes the computed representations. It does not rewrite the embedding table.

The coefficients often called “attention weights” are input-dependent activations. The Q/K/V projection matrices are stored parameters.

Base model, pretrained model and instruction model

A pretrained model has already learned from a corpus. A base language model usually refers to a model before instruction-focused adaptation. An instruction model has been trained to respond to requests in a particular interaction format. “Base” can also mean the starting checkpoint for an adapter, which may itself be an instruction model.

In this workshop: after.pt is a tiny story-trained base for the biology adapter. It was never trained to answer chat instructions.

Assistant, product and agent

An assistant product combines models with an interface and potentially retrieval, tools and stored conversation state. An agent is a system that uses a model within a loop to choose actions or tools and use their results. These surrounding components are different from the transformer calculation itself.

Example: retrieving a document, reading its result and then drafting an answer is a system workflow. Our tiny prediction browser does not implement an autonomous agent.

2. Text, tokens and examples

TokenTokenizerVocabulary / IDSubword / BPESpecial token / UNKPrompt / contextContext windowDataset / corpus / recordJSONL / chat templateTarget / next-token task

Token

One unit processed by a model's tokenizer. Depending on the tokenizer, it can be a character, a word, part of a word, punctuation or a special marker. A token is not universally a whole word.

In this workshop: the cat sat. contains 12 character tokens, including its spaces and full stop. An illustrative whole-word tokenizer could produce [the] [cat] [sat] [.].

Tokenizer, encoding and decoding

A tokenizer defines how text is divided into pieces and mapped to IDs. Encoding applies those rules to text. Decoding maps IDs back to pieces and assembles text. The tokenizer must match the trained model.

Example: repeated a characters always receive the same ID in the fixed classroom vocabulary. They do not receive new random numbers on each run.

Tokenizer decoding is not the same thing as a transformer decoder block or a sampling policy.

Vocabulary and token ID

The vocabulary is the list of available tokens. A token ID is an integer that identifies one entry. It acts like a row address, not a definition or a measure of meaning.

Invented word vocabulary: [<UNK>, the, cat, sleeps] maps “the cat” to [1, 2]. These are not the live browser's character IDs.

Changing a trained model's ID mapping without correspondingly changing its weights breaks the interpretation of its inputs and outputs.

Subword and BPE — byte-pair encoding

A subword token may be part of a word or an entire word. A simple BPE procedure repeatedly merges frequent adjacent token pairs in training text, then saves the merge rules. Encoding later applies those fixed rules; it does not retrain the language model.

Illustrative split: “cats” might become [cat] [s]. The actual split depends on the tokenizer. Our optional BPE script shows merges using “low”, “lower” and “newer”.

The workshop BPE example is a small character-based illustration, not a production byte-level tokenizer or an integrated subword language model.

Special token, <UNK>, padding and end markers

A special token represents a convention such as unknown input, padding or the end of a sequence. The model and tokenizer must agree on its meaning and use. Merely writing a new marker does not teach that convention.

In this workshop: ID 0 is reserved for <UNK>. Its display spelling has several characters, but it represents one token ID. The strict classroom encoder rejects unsupported input characters; generation can still choose the reserved ID.

The character setup stops by token budget or context limit. The word companion adds START and END markers and learns to predict END after a sentence; it also enforces a context limit.

Prompt and context

The prompt is the initial input supplied to the model. Context is the input available for a prediction, including the prompt, any retrieved passages and tokens generated so far. A prompt can be a fragment, not necessarily a question.

Example: starting with the and generating b gives the next prediction the context the b.

Context window / block size

The maximum number of token positions a model processes together in a particular setup. It is measured in tokens, not necessarily words or characters. Longer text needs a stopping, truncation or sliding-window policy.

In the character route: the browser allows 64 IDs and the Python generator keeps a sliding 64-ID context. Character training uses 32-position windows. The word companion has 16 positions including START, trains on complete short sentences and stops on END or a full context.

Dataset, corpus and record

A dataset is a collection of examples. A text corpus is a collection of text. A record is one structured entry and can contain several fields, messages or sentences. A collection of 100 records does not necessarily contain 100 sentences.

Example: one biomedical record contains a question, a multi-sentence abstract and a target decision. The tiny story corpus contains five records, which together contain 20 sentences under our documented counting rule.

JSONL, message records and chat template

JSONL stores one JSON object per line. A chat record may have user and assistant messages. A chat template converts those structured roles and messages into the exact text/token convention expected by a particular instruction model.

Example: a user message asks for financial sentiment; the assistant target is neutral. The raw field names such as messages need not be literal text sent to the model.

The tiny character model uses plain text; it does not use the pretrained instruction model's chat template.

Target and next-token prediction

A target is the observed answer used to score a prediction during training or evaluation. For next-token prediction, the text itself provides the targets: shift the sequence one position to the left relative to the inputs.

Character example: inputs [t, h, e] pair with targets [h, e, space]. At each position, the model predicts the following character.

A causal mask prevents a position from seeing later input positions, even when the training sequence contains them.

3. The numbers inside the model

Scalar / vector / matrix / tensorEmbeddingPosition embeddingLinear layer / projectionAttentionQuery / key / valueCausal maskHead / block / layerLayer normalizationResidual connectionFeed-forward networkLogit / LM headSoftmax

Scalar, vector, matrix, tensor and shape

A scalar is one number. A vector is a list of numbers. A matrix has rows and columns. A tensor is the general name for an array with dimensions. Its shape says how many entries each dimension has.

In this workshop: 12 token positions with 64 features each form a 12 × 64 matrix. With a batch dimension, this can be 1 × 12 × 64.

The 64 features are coordinates in each vector, not 64 words or 64 attention heads.

Embedding and embedding table

An embedding is a vector representation. The token embedding table stores a learned vector for each vocabulary ID. The first step is a lookup: retrieve the row for each input ID. Later blocks compute context-dependent representations from these initial vectors.

Example: the three a's in aaa retrieve the same token embedding. Their final representations can differ because their positions and available context differ.

An untrained embedding is not a meaningful dictionary definition. Individual coordinates do not come with predetermined human labels.

Position embedding

A vector that supplies information about where a token occurs. Our model looks it up in a learned position table and adds it to the token vector. Other architectures can represent position differently.

Invented coordinate: token value 0.2 plus position value -0.1 gives 0.1. Adding two 64-feature vectors leaves 64 features.

Linear layer, projection and dot product

A linear layer forms weighted sums of input coordinates, usually with an added bias. A projection maps a representation into another set of coordinates. A dot product multiplies corresponding coordinates of two vectors and sums the results.

Invented dot product: [1, 2] · [3, 4] = 1×3 + 2×4 = 11. Attention uses dot products between queries and keys to calculate matching scores.

Attention / self-attention

Attention lets a position combine information from other allowed positions. It calculates matching scores, converts them to mixing coefficients and takes a weighted sum of value vectors. Self-attention gets queries, keys and values from representations of the same sequence.

Invented mixture: weights [0.25, 0.75] combine values as 0.25 × V₁ + 0.75 × V₂.

Attention coefficients describe information mixing. They are not word importance for every purpose, factual confidence or a complete explanation of the prediction.

Q, K and V — query, key and value

These are three learned projections of each representation. A query is compared with keys to calculate scores. Values are the vectors that will be mixed using the resulting attention coefficients. “What am I looking for?”, “what do I match?” and “what information do I supply?” are useful analogies, not literal internal questions.

In this workshop: one head has 32 query coordinates, 32 key coordinates and 32 value coordinates per position. The score between reader i and source j comes from Qᵢ and Kⱼ.

Causal mask

A rule that blocks access to later positions. The next-token predictor must not use future text to solve its training exercise. Our model sets disallowed scores to negative infinity before softmax, making their mixing coefficients zero.

Example: position 0 can read only itself, so its attention coefficients are [1, 0, 0, …]. That does not mean the model is accurate; it means the mask is working.

Attention head, layer and transformer block

A head performs one attention computation using its projected coordinates. Multiple heads provide multiple learned ways of mixing information. A layer is a component calculation; a block groups several components, including attention and a feed-forward network.

In this workshop: each of two blocks has two attention heads. Two 32-feature head outputs are concatenated into 64 features, then projected.

Heads are not assigned fixed topics such as “grammar” or “biology” by this code.

Layer normalization

A calculation that centers and rescales a position's feature values, with a small numerical stabilizer and learned scale/offset parameters. It helps control the numerical scale flowing through the network.

In this workshop: each block normalizes its input before attention and again before its feed-forward transformation. The normalized row is not a probability distribution.

Residual connection

A connection that adds a transformation's output to an earlier representation. It provides a path for the earlier information while letting the block learn an adjustment.

Code idea: x = x + attention(normalize(x)). The addition requires compatible shapes; it does not double the feature count.

Feed-forward network / MLP / activation function

The feed-forward part applies learned transformations to each position separately after attention has mixed information between positions. MLP means multi-layer perceptron. An activation function such as GELU introduces a nonlinear transformation between linear layers.

In this workshop: the block expands 64 features to 256, applies GELU, then maps back to 64. The same learned transformation is applied at each position.

Logit and language-model head

A logit is an unnormalized score for a possible output token. The language-model head is the final projection from a contextual representation to one score per vocabulary entry.

In this workshop: the final 64-feature vector becomes 32 next-character scores. Scores may be negative and do not have to sum to one.

Softmax and probability distribution

Softmax exponentiates scores and divides by their total, turning them into nonnegative values that sum to one. In attention these values weight source positions; at the output they assign probabilities to vocabulary tokens.

Invented example: equal scores for three alternatives become probabilities [1/3, 1/3, 1/3].

A next-token probability is not a probability that a whole answer is factually correct. Attention softmax and vocabulary softmax normalize over different things.

4. Training and saved state

Training / pretrainingForward passTeacher forcingLoss / cross-entropyGradient / backpropagationOptimizer / learning rateBatch / step / epochDropout / train and eval modesCheckpoint / resumeSeed / reproducibility

Training, training from scratch and pretraining

Training uses examples, a loss and an update rule to adjust parameters. Training from scratch starts with a newly initialized model. Pretraining learns an initial capability from a corpus before later adaptation; it does not imply a particular amount of knowledge.

In this workshop: topic 004 starts from random initialization and practices next-character prediction on three short stories. One hundred updates are real training, but do not make a useful assistant.

Forward pass

Computing outputs from inputs using the current parameters. It includes embedding lookup, transformer blocks and output scores. A forward pass can be used during both training and inference; by itself it does not change weights.

Example: typing aba in the browser recomputes the forward pass and updates the visible matrices without running an optimizer.

Teacher forcing

During next-token training, each prediction is conditioned on the correct preceding text from the dataset. During free generation, later predictions instead depend on the model's earlier choices. This difference helps explain why a model can have improving loss but still drift into nonsense.

Example: practice supplies the correct prefix the bo when scoring the next character. Generation may have already produced the bi, creating a different problem.

Loss and cross-entropy

Loss is the penalty the training process tries to reduce. For our next-token task, cross-entropy is the average of −ln(probability assigned to the observed target). It rewards assigning more probability to the actual next token.

Invented example: target probability 0.1 gives a penalty about 2.303; probability 0.5 gives about 0.693. The target can become more probable without becoming the top choice.

Loss is not an accuracy percentage, a fluency score or proof of factual knowledge. The natural-log unit is called a nat.

Gradient, backpropagation and gradient clipping

A gradient describes how a small parameter change would affect the loss locally. Backpropagation efficiently computes these derivatives through the operations. Clipping limits the overall size of a gradient before an update, which can help avoid excessively large updates.

In Python: loss.backward() computes gradients; the classroom code then clips their norm before calling the optimizer. Backpropagation itself is not the optimizer update.

Optimizer, AdamW and learning rate

An optimizer uses gradients to update parameters. AdamW also maintains running information about gradients and applies weight decay. The learning rate controls the update scale; it is not a target loss or a percentage of knowledge to acquire.

In this workshop: optimizer.step() changes the parameters. The scratch classroom run uses a learning rate of 0.003.

In the desktop classroom UI, changing the learning-rate dropdown does not alter an already created optimizer. Start a new run with the desired setting.

Batch, training step, epoch and gradient accumulation

A batch is a group of examples processed together. A training step here is one optimizer update. An epoch is one pass through the dataset. Gradient accumulation combines gradients from several smaller batches before one update.

In topic 004: one update uses four random 32-character windows. --steps 100 requests 100 updates, not 100 epochs. --step is a separate option that pauses printed output.

Dropout, training mode and evaluation mode

Dropout randomly removes some intermediate contributions during training as a regularization technique. Evaluation mode disables dropout's training behavior so measurements and inference use a stable computation.

Example: model.eval() does not erase learning or make a model “untrained”. A trained model still has its learned weights in evaluation mode.

Evaluation mode and disabling gradient tracking are separate controls in PyTorch.

Checkpoint, snapshot and exact resume

A checkpoint saves model state. To interpret it, loading also needs the matching architecture and tokenizer. Exact training resume requires more state, including the optimizer, progress and random-number state.

In this workshop: before.pt and after.pt support inference/comparison but omit optimizer-resume state. The separate tiny.py trainer saves more complete training checkpoints.

The browser's before/after buttons load exported parameter sets; they do not train in JavaScript.

Random seed and reproducibility

A seed sets the starting state of a pseudo-random generator. It helps repeat initialization, batch selection or sampling when the rest of the experiment is held fixed. A seed alone does not guarantee bit-identical results across hardware and software versions.

In this workshop: the classroom initialization uses seed 1337. For a meaningful comparison, also preserve the data, tokenizer, settings and decoding rule.

5. Generating text

InferenceAutoregressive generationSampling / greedy decodingTemperatureHallucination / gibberish

Inference

Using the current model to compute predictions. Inference normally leaves model parameters fixed. It can happen with trained weights or, for teaching, with randomly initialized weights.

Example: the browser calculates attention and next-character probabilities when you edit the prompt. No learning update occurs.

Autoregressive generation

Predict a next token, select one, append it to the context, and repeat. “Autoregressive” here means the continuation depends on the sequence produced so far. Each mistake can affect later predictions.

Example: the → the b → the bo → the boi. The model does not first write a complete sentence and then reveal its characters.

Sampling, greedy decoding and decoding policy

A decoding policy decides how scores become a chosen output token. Sampling draws according to probabilities. Greedy decoding always chooses the highest-scoring token. Sampling can produce different continuations with unchanged weights.

Invented probabilities: if a: 0.6 and b: 0.4, greedy chooses a, while sampling can choose b. Different sampled text does not prove learning.

Topic 005 samples by default. Topics 004 and 008 use greedy generation for their fixed comparisons.

Temperature

A positive number used to divide logits before sampling softmax. Lower values make the distribution more concentrated; higher values flatten it. It changes how alternatives are selected, not the stored model parameters.

Browser exercise: compare 0.2 and 2.0 on the same prompt before generating. The probability bars change. If greedy mode is selected, the highest-score choice stays the same.

Low temperature does not verify facts. In TinyGPT.generate, a temperature argument of zero is a special instruction to use greedy selection, not division by zero.

Hallucination and gibberish

“Hallucination” commonly describes generated claims unsupported by the relevant evidence or facts, even when they sound fluent. Gibberish is malformed or meaningless text. These are different failure modes and need different checks.

Example: the boa pe a bond is visibly poor text. A fluent but invented room number is a factual error that requires checking against the handbook.

6. Adapting models and supplying evidence

Fine-tuning / SFTContinued pretrainingLoRA / adapter / rankQuantization / QLoRAMerged adapterFew-shot promptingRAG / retrievalChunk / retrieval indexTF-IDF / cosine similarity

Fine-tuning and SFT — supervised fine-tuning

Fine-tuning continues training from an existing model. SFT uses desired outputs for supplied inputs, such as user questions paired with assistant responses. The training objective and the choice of trainable parameters are separate decisions.

Example: train on financial-sentence requests whose desired answers are sentiment labels. The pretrained pipeline computes its supervised loss on the final assistant response.

Fine-tuning can use all parameters or an adapter. The tiny biology prose exercise is not instruction SFT.

Continued pretraining / prose adaptation

Continue next-token training on text, rather than on explicit instruction/answer pairs. This can adapt language patterns, but does not by itself establish reliable instruction following or factual recall.

Example: training on “the plant needs light and water.” practices continuing prose. Training on “What does the plant need?” paired with an answer is a different data format and objective.

LoRA, adapter, frozen base and rank

LoRA means low-rank adaptation. It keeps a base weight matrix fixed and learns two smaller matrices whose product supplies an adjustment: W_effective = W_base + (alpha/rank) × B × A. “Frozen” means the optimizer does not update those base parameters. Rank controls the intermediate size of the adjustment.

In this workshop: the output matrix has 32 outputs and 64 inputs. Rank 4 gives A with shape 4 × 64 and B with shape 32 × 4: 256 + 128 = 384 trainable numbers.

Rank 4 does not mean four topics, four layers or four training examples. The small adapter cannot guarantee useful knowledge when the base is very weak.

Quantization and QLoRA

Quantization represents numbers using a reduced set of values or fewer bits, trading numerical precision for storage/memory savings. QLoRA trains low-rank adapters while keeping a quantized base frozen. It does not mean that every training value or computation uses the same low-bit format.

In this project: the separate pretrained biology preset requests QLoRA. The tiny browser and CPU adapter exercise do not simulate QLoRA.

A low-bit base does not remove all training memory costs; activations and trainable state still need memory.

Merging an adapter

In the tiny LoRA lab, merging adds the learned matrix adjustment into a copy of the base weight matrix. The resulting model can run through the ordinary tiny-model inference code without a separate LoRA wrapper.

In this workshop: merged.pt is the adapted tiny model. adapter_matrices.pt stores the small matrices separately. These files are not pretrained PEFT adapter files.

Few-shot prompting and in-context examples

Put a few demonstrations in the input to show the requested pattern. The examples can influence the current prediction without an optimizer update. “In-context learning” describes this behavioral effect, not permanent parameter training during the forward pass.

Example: include two sentences with sentiment labels before asking for a third. The examples are part of the prompt and consume context space.

Retrieval and RAG — retrieval-augmented generation

Retrieval searches a collection for relevant material. A RAG system supplies selected material in the model's input and then generates a response. The retrieval step does not train the generator's weights.

Browser exercise: change Neral's room from K142 to M219. The retrieved evidence and assembled prompt change. This browser activity stops there: it does not generate an answer.

Finding the correct passage and producing a faithful answer are two separate things to evaluate.

Document chunk and retrieval index

A chunk is a passage treated as one searchable unit. An index is a representation organized to help find relevant units, using terms, vectors or other structures. A chunk commonly contains many tokens.

Example: one handbook passage about an instrument's room can be one retrieval chunk. It is then tokenized along with the rest of the prompt before a language model processes it.

Document chunking and tokenization solve different problems.

TF-IDF and cosine similarity

TF-IDF represents text using term frequency and how common each term is across documents. Cosine similarity compares the direction of two vectors; vectors pointing in similar directions score more highly. This supports lexical retrieval without a neural generator.

In Python topic 007: the question and passages become TF-IDF vectors and are ranked by similarity. The browser uses simpler matched-word overlap, so its scores are not the Python TF-IDF scores.

7. Evaluation, measurement and hardware

Train / validation / testOverfitting / generalization / leakageBaseline / controlled comparisonAccuracy / F1 / invalid labelsPerplexityManifest / hash / revisionCPU / GPU / VRAM / CUDAFP32 / FP16 / BF16

Training, validation, test and held-out data

Training data supplies learning updates. Validation data helps choose settings or checkpoints without supplying gradient updates. Test data is reserved for evaluating the selected procedure. “Held out” means excluded from the relevant training process.

In this workshop: three stories train the tiny model; two separate stories supply validation text. There is no separate tiny-story test split.

Repeatedly choosing settings by test results makes the test set part of the selection process.

Overfitting, generalization and data leakage

Overfitting means fitting training-specific details in a way that does not transfer well to the intended new examples. Generalization is performance on relevant unseen examples. Data leakage occurs when information that should be held out improperly influences training or selection.

Example: a model can memorize a room assignment yet fail a differently worded question. Putting duplicate examples in both train and test can make performance look better than it really is.

A tiny validation fluctuation alone does not prove overfitting. Consider the size and design of the measurement.

Baseline and controlled comparison

A baseline is the reference condition against which a change is measured. A controlled comparison holds important settings fixed so that the intended change can be interpreted.

Example: compare the same base model with and without an adapter, using the same tokenizer, prompts and greedy decoding. Changing the prompt and sampling policy at the same time makes the effect harder to interpret.

Accuracy, precision, recall, F1 and invalid-label rate

Accuracy is the fraction of predictions that are correct. For one class, precision asks how many predictions of that class were right; recall asks how many actual members of that class were found. F1 combines precision and recall using their harmonic mean. Macro F1 averages per-class F1, giving each class equal weight.

Invented example: 8 correct decisions out of 10 gives 80% accuracy. If a finance task permits only three labels, “I am not sure” is an invalid label that should also be reported.

A metric must match the task. Exact word-for-word agreement with one example email is not a complete measure of email quality.

Perplexity

For mean cross-entropy measured with natural logarithms, perplexity is exp(loss). It summarizes how much probability the model assigned to observed targets. Lower is better only under a comparable evaluation setup.

Invented example: loss ln(4) corresponds to perplexity 4. This can be understood as an effective uncertainty scale, not literally four equally likely choices at every position.

Per-token losses and perplexities from a character tokenizer and a word tokenizer are not directly comparable.

Manifest, source hash and revision

A manifest records what an artifact contains and where it came from. A cryptographic hash is a fingerprint of particular bytes or text; a revision identifies a source version. They help distinguish experiments that used different data or model files.

Example: the finance manifest records its source revision, split sizes and file hashes. A changed hash means the hashed content differs; it does not mean the data became better or worse.

CPU, GPU, VRAM and CUDA

A CPU is the general-purpose processor. A GPU can perform many numerical operations in parallel. VRAM is the GPU's own memory. CUDA is the NVIDIA computing platform used by compatible software to run GPU work.

For this workshop: the supplied RTX 2080 report shows 8,192 MiB of VRAM, some already used by the desktop. The browser and character classroom scripts do not require it. The word trainer and optional word adapter were run on the detected RTX 2080 SUPER; their commands also support CPU.

A GPU appearing in nvidia-smi does not prove that a particular Python interpreter can use it. Check torch.cuda.is_available() in the environment that will run training.

FP32, FP16, BF16 and mixed precision

These are floating-point number formats with different precision and range. Mixed-precision training uses different formats for different parts of the computation to manage speed and memory. Hardware and software must support the selected formats.

In the existing finance preset: fp16: true and bf16: false select the intended precision mode. They do not describe the number of model parameters or guarantee that the whole run fits in memory.

Five distinctions to remember

  1. ID versus embedding: an integer address versus a vector looked up at that address.
  2. Parameter versus activation: a stored number versus a value computed for this input.
  3. Inference versus training: use current weights versus update them using examples.
  4. Retrieval versus fine-tuning: supply evidence in context versus train selected parameters.
  5. Better measured prediction versus useful answers: related goals that require different evidence.

Keep asking: What is the input? What is being predicted? What changed? How would we know it improved?
