What is happening?

Core idea

There are two levels in this topic. The desktop and demo.py implement real LoRA optimization on the output head of our tiny character model. A and B are trainable; all original parameters are frozen and checked for exact equality after updates. The resulting effective matrix is W + (alpha/r) B A. B starts at zero, so initially the adapter leaves the base output unchanged. This demonstrates low-rank mechanics on fictional domain prose. train_pretrained.py instead calls the existing Hugging Face/PEFT training pipeline for an actual pretrained instruction model.

Show it step by step

  1. First train/load the tiny base from 004, or explicitly label a random-base run as mechanics only.
  2. Select a domain and rank. Start a new adapter and watch its delta matrix and training loss.
  3. Compare greedy base and adapter text for the same prompt.
  4. Save and compare merged.pt against the original base checkpoint in 008.
  5. For a real domain experiment, follow the pretrained workflow below and retain a held-out dataset.
Change one thing

DOMAIN_TEXTS contains the small fictional prose samples. Change domain or rank and start a new adapter. Preserve the same base for comparisons; do not successively adapt one domain from a different domain adapter unless studying that specific effect. The UI trains 60 updates per new adapter. Its chart is adaptation training loss, not held-out task performance.

Questions to discuss

Why does rank matter? It changes the capacity and number of parameters in the update. What is QLoRA? Training adapters over a quantized frozen base, supported in the real pretrained pipeline. Is the tiny UI pretending to run QLoRA? No.

Interpret the result carefully

Tiny adapter_matrices.pt files are not PEFT format. merged.pt is a normal TinyGPT checkpoint. Prose adaptation is not supervised instruction fine-tuning. Neither teaches guaranteed factual recall.
