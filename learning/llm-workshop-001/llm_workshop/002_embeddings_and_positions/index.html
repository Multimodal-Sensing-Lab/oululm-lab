What is happening?

Core idea

We use the actual token and position embedding tables of the shared TinyGPT. Every token ID addresses one row. The embedding width is 64 in the default model. The plots show the first eight features to keep the view readable; a feature column is not assigned a human concept. A repeated token has the same token vector, but adding the position vector changes the combined representation. The initial model is untrained, so geometric patterns must not be presented as learned semantics.

Show it step by step

  1. Type aaa and identify identical rows in the token panel.
  2. Compare those rows in the position panel; each location has a different vector.
  3. Inspect the combined panel and explain elementwise addition.
  4. Train in topic 004 or load a checkpoint, return here, and distinguish changed parameters from a changed input.
Change one thing

Change --text in the terminal or the input field in the desktop. Keep the same shared model for a controlled comparison. In demo.py, inspect the three operations in inspect(): lookup token vectors, lookup position vectors, then add.

Questions to discuss

Why is an integer ID not a meaning vector? It only selects a row. Why do repeated tokens have different inputs to attention? Position information is added. Does a colorful random matrix demonstrate semantics? No.

Interpret the result carefully

The implementation uses learned absolute positions. Other architectures may use sinusoidal or rotary schemes. Do not describe our table as universal.
