How a language model produces text

Keep these five ideas. We will open the boxes one at a time.

Blue · definitionGreen · worked example / say aloudAmber · common confusionPurple · optional depth
1. Text → tokens → IDs

A tokenizer cuts text into pieces and looks up their ID numbers. Today each character is one token. Other tokenizers use words, subwords or bytes.

↓
2. IDs → vectors

An embedding table provides a list of numbers for each token. Position information tells the model where it occurs.

↓
3. Vectors → transformer blocks

Attention combines information from allowed positions. Other layers transform it. The same architecture is used before and after training.

↓
4. Features → scores → probabilities

The model assigns a score to each possible next token. Softmax turns scores into a probability distribution.

↓
5. Choose → append → repeat

Select a token, add it to the input and predict again. Convert the resulting IDs back into text.

Training or inference?

Training changes weights.

Known examples let us calculate a prediction penalty called loss. Gradients and an optimizer adjust the weights to reduce it. Held-out examples check whether learning generalizes.

Inference uses the current weights.

The input and generated tokens change. The weights stay fixed. Temperature changes sampling; it does not train the model.

Today the network is untrained, not empty.

Its numerical weights already exist, but it has not learned from the stories. Random-looking output is expected. Token IDs are stable lookup numbers, not random weights.
