007 · Retrieval-augmented generation

Inspect the actual evidence and exact prompt before asking a model to answer.

Computation source · Desktop launcher

What is happening?

Core idea

The offline demo treats each nonempty document line as a passage. A TF-IDF vectorizer builds a document vocabulary and normalized vectors. A query vector is compared with each passage by cosine similarity. Positive-scoring top passages become evidence in an augmented prompt. The green bars identify selected passages. This implements retrieval and prompt construction, not an invented model answer. answer_with_model.py adds actual inference using a locally staged instruction model and prints both no-retrieval and retrieval conditions.

Show it step by step

  1. Ask where the fictional Neral instrument is stored; inspect its source passage and score.
  2. Change K142 to M219 in that passage. The selected evidence and prompt update.
  3. Ask a question with no matching terms. No evidence is fabricated.
  4. Use related or ambiguous wording to show lexical retrieval limitations.
  5. When a local instruction model is staged, run answer_with_model.py to measure the final answer under both conditions.
Change one thing

Edit the question or the document text in the desktop. Terminal --documents accepts a UTF-8 file with one passage per line, and --top-k controls retrieval. The fixed corpus is deliberately small enough to inspect completely.

Questions to discuss

Is a passage the same as a model token? No; a passage contains many tokens. Did replacing the room number update model weights? No. Can the right document still lead to a wrong answer? Yes; retrieval and generation can fail separately.

Interpret the result carefully

TF-IDF is a lexical baseline, not a neural retrieval embedding model. The prompt preview alone proves only which evidence would be supplied. Actual generated answers require answer_with_model.py and a staged model.
