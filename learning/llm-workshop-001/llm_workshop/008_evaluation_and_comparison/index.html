008 · Evaluation and comparison

Separate measured model outputs from metric examples and control comparisons.

Run from learning/llm-workshop-001 in the workshop environment. The terminal pauses with Enter; the desktop provides editable controls and actual computations.

Computation source · Desktop launcher

What is happening?

Core idea

The default label list is a manually authored fixture for explaining accuracy, macro F1 and invalid outputs. It is conspicuously labeled in the terminal and desktop. Rows in the confusion matrix are reference labels; columns are predictions, including INVALID. Invalid responses count as errors. A separate command and UI action load two real TinyGPT checkpoints, apply the same prompt and greedy decoding, and display actual outputs. The existing compare_pretrained.py entry point evaluates real pretrained bases/adapters and can compare retrieval conditions.

Show it step by step

  1. Inspect the six fixed reference labels. Change one predicted label and observe the metric changes.
  2. Enter an unsupported response such as a sentence; it appears in the INVALID column.
  3. Load before.pt and after.pt from the same training run and compare actual text.
  4. Compare a trained base with merged.pt from a domain adapter, keeping the prompt fixed.
  5. Use held-out labeled data with compare_pretrained.py for real domain task metrics.
Change one thing

Terminal --left and --right must both be supplied for real checkpoint comparison. The desktop has a Compare two checkpoints action. Default fixtures can be edited in the prediction box. Comparisons require the same vocabulary; differing tokenizers invalidate this controlled path.

Questions to discuss

Why can a cherry-picked prompt be misleading? It does not measure general behavior. Why use macro F1 with uneven classes? It weights class-level F1 equally. Does fluent prose imply accurate domain knowledge? No.

Interpret the result carefully

The hand-written label fixture is never reported as measured model performance. Actual checkpoint generations are qualitative until scored against suitable references. Keep source, split, tokenizer and decoding settings with experiment results.
