What is happening?

Core idea

The Generation object keeps integer IDs internally. This matters for special/reserved tokens: the display spelling <UNK> must never be fed back as literal characters. The model computes scores from its current context; temperature rescales them before sampling. Greedy selection takes the largest score and does not use temperature. Sampling uses a separate seeded random generator. Merely redrawing the UI chart consumes no random draw and does not append a token.

Show it step by step

  1. Use a short prompt such as the . Inspect the vocabulary probabilities.
  2. Change temperature and compare the concentration; no weights changed.
  3. Click Next token. Identify its ID and the extended text. The chart now predicts the following token.
  4. Reset prompt, enable Greedy and repeat.
  5. Load a trained checkpoint or visit after topic 004 to compare useful patterns against the random baseline.
Change one thing

Terminal options include --checkpoint, --temperature, --greedy, --tokens and --step. The UI keeps the current generated ID sequence until Reset prompt or an input edit. Once the context grows beyond the model limit, the simple implementation uses its latest context window.

Questions to discuss

Why can two sampled continuations differ with identical weights? Random selection. Does temperature teach vocabulary or facts? No. Why keep prompt and decoding fixed when comparing checkpoints? Otherwise output changes have multiple causes.

Interpret the result carefully

The tiny tokenizer has no natural end-of-sequence token, so the terminal uses an explicit token budget. The model recomputes its context rather than using a KV cache. It is a transparent teaching implementation.
